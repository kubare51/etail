--------------------------------------------------------------------------------
TABLE 1: print_templates (PRIMARY TABLE)
--------------------------------------------------------------------------------

Purpose: Stores all print templates — their metadata, design data, and 
compiled HTML/CSS. Supports versioning (multiple versions per template group)
with active/inactive status.

Key Columns (inferred from model code):
  - id_template        (PK, AUTO_INCREMENT) — Unique template ID
  - template_code      (UNIQUE) — Unique code per version (e.g. "BILL_STD_A4_1712345678")
  - code               — Grouping code shared across all versions of same template
  - template_name      — Human-readable name (e.g. "Standard Sales Invoice")
  - template_category  — Category ID (0-15, maps to CATEGORIES constant)
  - paper_size         — Paper size (A4, A5, Letter, Thermal-58mm, Thermal-80mm, Custom)
  - page_orientation   — Portrait or Landscape
  - id_branch          — Branch ID (NULL = global/all branches)
  - is_default         — Whether this is the default template for its category/branch
  - is_active          — Whether this version is currently active (0/1)
  - version_number     — Sequential version number within the group
  - parent_template_id — ID of the previous version
  - template_html      — Compiled HTML output (Mustache-style with {{placeholders}})
  - template_css       — Compiled CSS for the template
  - gjs_data           — GrapesJS/Block Editor data as JSON (full design state)
  - updated_at         — Timestamp of last update

Used by: Both URL #1 (listing) and URL #2 (designer). Queried for listing,
read for designer load, written on save.

Versioning Model: Each save creates a NEW row with incremented version_number,
deactivates all other rows with the same `code`. This provides full version history.

--------------------------------------------------------------------------------
TABLE 2: print_template_placeholders
--------------------------------------------------------------------------------

Purpose: Stores available template placeholder variables ({{variable_name}})
that can be inserted into templates. Organized by category and group.

Key Columns (inferred from model code):
  - placeholder_key    — Variable key (e.g. "customer_name", "invoice_no")
  - placeholder_label  — Display label (e.g. "Customer Name")
  - sample_value       — Sample value for preview
  - category           — Template category this placeholder belongs to
  - placeholder_group  — Grouping (e.g. "Customer", "Bill Details", "Tax & Totals")
  - display_order      — Sort order within group
  - field_type         — Field type (text, number, etc.) — used by V2
  - is_loop_field      — Whether this field belongs to a loop (0/1) — used by V2
  - parent_loop        — Parent loop key if is_loop_field=1 — used by V2

Used by: Both the designer (Variable picker panel) and controller (get_fields endpoint).
NOTE: Dynamic placeholders are also generated in code (hardcoded in the model)
and merged with DB records. DB records take precedence.

--------------------------------------------------------------------------------
TABLE 3: print_template_mc_va_config
--------------------------------------------------------------------------------

Purpose: Stores MC (Making Charges) and VA (Value Addition) column configuration
per branch and document type. Controls how MC/VA columns appear in print templates.

Key Columns (inferred from model code):
  - id                 (PK) — Config ID
  - id_branch          — Branch ID (NULL = global)
  - document_type      — Document type this config applies to
  - [config columns]   — MC/VA display settings (show/hide, labels, formatting)

Used by: V2 designer only. Branch-specific with global fallback.

--------------------------------------------------------------------------------
TABLE 4: print_template_defaults
--------------------------------------------------------------------------------

Purpose: Stores pre-built default template definitions that can be loaded
as starting points when creating a new template. System-defined defaults
are prioritized over user-created ones.

Key Columns (inferred from model code):
  - id                 (PK) — Default template ID
  - template_category  — Category this default belongs to
  - is_system          — Whether this is a system-provided default (1 = system, 0 = user)
  - [template data]    — Block definitions JSON / HTML content

Used by: V2 designer (load_default_template endpoint).

--------------------------------------------------------------------------------
TABLE 5: print_template_custom_blocks
--------------------------------------------------------------------------------

Purpose: Stores user-saved custom blocks that can be reused across templates.
When a user customizes a block and clicks "Save as Block", it is stored here.
Table is auto-created if it doesn't exist.

Key Columns (from controller CREATE TABLE):
  - id                 (PK, AUTO_INCREMENT)
  - block_name         — User-given name for the custom block
  - block_html         — Full HTML content of the block
  - block_css          — CSS styles for the block
  - category           — Template category
  - created_at         — Timestamp

Used by: Designer page — "Save as Block" feature and custom block sidebar panel.
