### 2.4 Existing v1 Print behaviour (the pattern to imitate)

`#btn_stock_print` ([L12455](admin/assets/js/ret_reports.js#L12455)) does **not**
clone `outerHTML` — it rebuilds `thead` + `tbody` from scratch:

1. Walk `#stock_list thead tr:first th`, ask the live DataTable
   `dt.column(i).visible()`, collect visible indices.
2. Rebuild rows from `#stock_list tbody tr`, skipping `display:none` rows,
   preserving row/cell `color` (SUB TOTAL / GRAND TOTAL highlighting).
3. `window.open('', '_blank')` → `document.write(...)` → `win.print()` after 400 ms.

The Thermal Print should reuse this exact skeleton, changing only *which columns*
are extracted and *which CSS* is written.

## 3. Open Questions (must be answered before coding)

| # | Question | Why it matters | Assumption used in this document |
|---|---|---|---|
| **Q1** | ~~Which Pcs column?~~ **ANSWERED — but with a critical caveat.** | — | **Closing Stock pcs (col 13)**, and it **must be the JS-computed value**, not the model's. See box below. |
| **Q2** | Should the slip list **every** product row, or only rows with a non-zero pcs value? | Determines slip length; a full stock report can be 200+ rows = ~1.5 m of paper. | Print only rows with **Pcs > 0**, plus a TOTAL line. |
| **Q3** | Print timestamp from **browser clock** or **server clock**? | Browser clocks can be wrong; auditors may care. | Browser clock (`new Date()`) — no round-trip. Escalate if audit-grade time is required. |
| **Q4** | Paper width — **58 mm** or **80 mm**? | Column widths & font size differ. | **80 mm** (the common eTail POS roll), with a 58 mm variant behind a constant. |
| **Q5** | Should group headings (Metal / Section / Design, for Group By = 3 & 4) appear? | Affects readability vs length. | Yes — printed as bold, full-width separator lines. |
| **Q6** | Should SUB TOTAL / GRAND TOTAL rows carry over? | The A4 print preserves them. | Print only the **GRAND TOTAL** as a footer line; drop intermediate sub-totals. |
| **Q7** | Does "Old"/"New" map to v1/v2 as assumed? | Menu labels live in the DB `menu` table, not in the repo — could not be verified from source. | Old = `stock_details_v1`, New = `stock_details_v2`. |
| **Q8** | Should the button respect `allow_stock_type` (profile 2 = weight-only)? | A weight-only profile has the pcs columns hidden. | **Yes** — hide/disable Thermal Print when pcs columns are not visible (see §8 Risk R3). |

> ### ⚠ Q1 — there are TWO different "closing pcs"
>
> The model computes `closing_pcs` as `IFNULL(current.piece,0)` — an independent
> `≤ ToDt` tag snapshot. **The grid never reads it.** The number the user sees is
> computed in the browser at [ret_reports.js:11885](../../admin/assets/js/ret_reports.js#L11885):
>
> ```
> closing_pcs = op_blc_pcs + inw_pcs − (sold_pcs + br_out_pcs + ret_pcs + iss_pcs)
> ```
>
> These are **different numbers**. A server-side slip that selects `closing_pcs`
> from the model will disagree with the screen — the exact print-vs-save divergence
> CLAUDE.md prohibits. This single fact is why §4 Option A (read the grid) is
> correct and Option B (re-query) is not.
>
> Note also that the **summary panel** uses a third formula (`op+inw−sold−br_out`,
> omitting `ret`/`iss` — defect C2), so the summary tile already disagrees with the
> grid total today. The slip must match the **grid**.

## 4. Design Options

### Option A — Client-side (recommended) ✅

Add a **Thermal Print** button that reads the already-rendered `#stock_list` grid
and opens a narrow print window, exactly mirroring the existing `#btn_stock_print`.

**Pros**
- Zero controller / model / SQL change → **no risk to stock figures**.
- Automatically honours every active filter (branch, date range, metal, purity,
  category, grouping, product, design, sub-design, list-by).
- Automatically honours ColVis and `allow_stock_type` profile permissions.
- Guaranteed print-matches-screen — satisfies the CLAUDE.md rule
  *"Save formula must match print formula"* by construction (it re-reads the
  same numbers the user is looking at).
- No second query = no chance of the slip disagreeing with the grid.

**Cons**
- Depends on the DOM being populated (button must stay hidden until a search runs —
  same rule the existing bar already follows).
- Cannot be re-printed from a URL / cannot be triggered server-side.

### Option B — Server-side print view

New controller case (e.g. `stock_details_v1/thermal_print`) + new view
`ret_reports/print/stock_thermal.php`, re-running the model with the same `$_POST`.

**Pros** — Bookmarkable/re-printable; PHP-side formatting.
**Cons** — Re-runs an already slow query ([performance index migration exists](database/migrations/20260607_000001_stock_report_performance_indexes.sql)); duplicates ~600 lines of aggregation logic that lives in the JS, creating a *second* source of truth for closing-stock arithmetic — a textbook print-vs-save divergence bug. **Rejected.**

> **Recommendation: Option A.**

### 5.3 Step 2 — shared helper in `ret_reports.js`

Place at file scope (not inside the AJAX success callback) so both v1 and v2 can call it.

```js
// ── Thermal slip builder — shared by Stock Report v1 (Old) and v2 (New) ──────
// Reads the already-rendered #stock_list grid so the slip can never disagree
// with what the user is looking at.  Column indices per the 20-column header:
//   0 = Category/Product,  1 = Op pcs,  5 = I/W pcs,  9 = O/W pcs,  13 = Closing pcs
var STOCK_THERMAL_PCS_COL   = 13;   // Q1 — Closing Stock pcs
var STOCK_THERMAL_NAME_COL  = 0;
var STOCK_THERMAL_WIDTH_MM  = 80;   // Q4 — set 58 for narrow rolls

function buildStockThermalHtml() {
    var branchName = $('#branch_name').val()
        || $('#branch_select option:selected').text()
        || '';
    var dtRange  = $('#dt_range').val() || '';
    var now      = new Date();
    var pad      = function (n) { return (n < 10 ? '0' : '') + n; };
    var printedOn = pad(now.getDate()) + '/' + pad(now.getMonth() + 1) + '/' + now.getFullYear()
                  + ' ' + pad(now.getHours()) + ':' + pad(now.getMinutes()) + ':' + pad(now.getSeconds());

    var rows = [];
    var totalPcs = 0;

    $('#stock_list tbody tr').each(function () {
        if ($(this).css('display') === 'none') { return; }        // filtered out
        var $tds = $(this).find('td');
        var name = $tds.eq(STOCK_THERMAL_NAME_COL).text().trim();
        var pcsTxt = $tds.eq(STOCK_THERMAL_PCS_COL).text().trim();
        var pcs = parseFloat(pcsTxt.replace(/,/g, ''));

        // Group heading rows (Group By 3/4) use colspan=2 on col 0 with no numbers.
        var isHeading = $tds.length < 3 || $tds.eq(STOCK_THERMAL_NAME_COL).attr('colspan');
        if (isHeading && name) { rows.push({ heading: true, name: name }); return; }

        if (!name) { return; }
        if (/grand total/i.test(name)) { return; }                // handled as footer

        // Defect C11/V1: closing goes NaN when no branch is selected (v1) or for
        // net weight (v2).  Surface it as '?' — never print a silent blank, and
        // never let NaN poison the total.
        if (isNaN(pcs)) { rows.push({ heading:false, name:name, pcs:'?', bad:true }); return; }

        // ⚠ Defect C38 LIMITATION: the grid renders every negative as an empty
        // cell, so a negative closing reaches us as '' → NaN, indistinguishable
        // from a genuine NaN above.  Reading the DOM CANNOT recover negatives.
        // Fixing this requires changing the grid renderer itself (js 11894-11913)
        // to stop swallowing negatives — tracked as C38, out of scope here.
        if (pcs === 0) { return; }                                // Q2 — skip true zeros only

        totalPcs += pcs;
        rows.push({ heading: false, name: name, pcs: pcs });
    });

    var body = '';
    for (var i = 0; i < rows.length; i++) {
        body += rows[i].heading
            ? '<tr class="grp"><td colspan="2">' + rows[i].name + '</td></tr>'
            : '<tr><td class="nm">' + rows[i].name + '</td>'
            + '<td class="pcs">' + rows[i].pcs + '</td></tr>';
    }

    return ''
      + '<html><head><meta charset="utf-8"><title>Stock Thermal</title><style>'
      + '@page{size:' + STOCK_THERMAL_WIDTH_MM + 'mm auto;margin:2mm;}'
      + 'body{width:' + (STOCK_THERMAL_WIDTH_MM - 6) + 'mm;margin:0;padding:0;'
      +      'font-family:"Courier New",monospace;font-size:11px;line-height:1.25;color:#000;}'
      + '.ctr{text-align:center;}'
      + '.branch{font-size:14px;font-weight:bold;text-transform:uppercase;}'
      + '.meta{font-size:10px;}'
      + 'hr{border:none;border-top:1px dashed #000;margin:3px 0;}'
      + 'table{width:100%;border-collapse:collapse;}'
      + 'td{padding:1px 0;vertical-align:top;word-break:break-word;}'
      + '.nm{text-align:left;width:70%;}'
      + '.pcs{text-align:right;width:30%;}'
      + '.grp td{font-weight:bold;text-transform:uppercase;padding-top:3px;}'
      + '.tot td{font-weight:bold;border-top:1px dashed #000;padding-top:2px;}'
      + '</style></head><body>'
      + '<div class="ctr branch">' + branchName + '</div>'
      + '<div class="ctr meta">STOCK IN &amp; OUT</div>'
      + (dtRange ? '<div class="ctr meta">Period: ' + dtRange + '</div>' : '')
      + '<div class="ctr meta">Printed: ' + printedOn + '</div>'
      + '<hr>'
      + '<table><tr class="grp"><td class="nm">PRODUCT</td><td class="pcs">PCS</td></tr></table>'
      + '<hr>'
      + '<table>' + body + '</table>'
      + '<table><tr class="tot"><td class="nm">TOTAL</td>'
      +        '<td class="pcs">' + totalPcs + '</td></tr></table>'
      + '<hr>'
      + '<div class="ctr meta">*** End of Report ***</div>'
      + '</body></html>';
}

function openStockThermalPrint() {
    var html = buildStockThermalHtml();
    var win = window.open('', '_blank', 'width=380,height=640');
    if (!win) { alert('Please allow pop-ups to use Thermal Print.'); return; }
    win.document.write(html);
    win.document.close();
    win.focus();
    setTimeout(function () { win.print(); }, 400);   // same delay as #btn_stock_print
}
```

## 6. Thermal Layout Specification (proposal — pending reference)

Target: 80 mm roll (~72 mm printable, ~48 monospace chars at 11 px).

```
        ┌──────────────────────────────────┐
        │        MAIN SHOWROOM             │  ← Branch Name (bold, centred, caps)
        │        STOCK IN & OUT            │  ← Report title
        │   Period: 01/07/2026 - 21/07/2026│  ← Filter date range
        │   Printed: 21/07/2026 18:42:07   │  ← Date & time of print
        ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
        │ PRODUCT                     PCS  │  ← Column header
        ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
        │ GOLD                             │  ← Group heading (Group By 3/4 only)
        │ Ring                          42 │
        │ Chain                         18 │
        │ Bangle                         9 │
        │ SILVER                           │
        │ Anklet                        27 │
        ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
        │ TOTAL                         96 │  ← Bold, dashed rule above
        ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
        │        *** End of Report ***     │
        └──────────────────────────────────┘
```

**Rules**
- Monospace (`Courier New`) so the pcs column stays aligned across rows.
- Product name column 70 % width with `word-break:break-word` — long product names
  wrap onto a second line rather than pushing the pcs column off the paper.
- Pcs right-aligned, integer, no thousands separator under 1,000
  (the grid uses `money_format_india()`; the helper strips commas before summing
  and re-emits a plain integer).
- `@page { size: 80mm auto; }` — `auto` height so the roll cuts at content end.
- No logo/image — keeps thermal print fast and avoids the base64 logo embedding
  used by A4 templates such as [bt_category_print.php:480-485](admin/application/views/branch_transfer/bt_category_print.php#L480-L485).

> [estimation_thermal.css](admin/assets/css/estimation_thermal.css),

| T23 | Client configured `allow_bill_type = 2` (EDA-only), v2 | Defect V3 makes Sold permanently 0 → closing overstated. Slip inherits it. Confirm the client's `allow_bill_type` before sign-off |

**T19 is the acceptance gate** — per CLAUDE.md, *"If report aggregates differently
from what save wrote → that's a bug."* The slip total must equal the on-screen

### Detail worth knowing

**The non-tag label map differs from tagged at `group_by = 3`.** The non-tag query
selects no `weight_range` column, so it falls back to `section_name` — mirroring
[ret_reports.js:11994](../../admin/assets/js/ret_reports.js#L11994). Using the tagged
map for both would have silently dropped every non-tag row under Section grouping.

**Rows are aggregated by label** across the whole nesting, so one product appearing
under two metals prints once with a combined figure. Zero-closing rows are skipped
(Q2 assumption — still unconfirmed).

**Defect C11 handled differently from the grid.** Where the model's no-branch variant
omits `ret_pcs`/`iss_pcs`, `_stock_num()` treats them as 0. The grid yields `NaN` and
renders a blank cell. **The slip therefore prints a number where the screen prints
blank** — deliberate, and arguably more correct, but it is a divergence. The real fix
is C11 itself.
