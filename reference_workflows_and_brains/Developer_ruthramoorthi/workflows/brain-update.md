# Phase 7 — Learn & Improve (Brain Update)

**SOP Reference**: [FINAL_SOP_BUG_REMEDIATION.md](file:///c:/xampp/htdocs/etail_development_src/SOP/FINAL_SOP_BUG_REMEDIATION.md) — Section 12 (Knowledge & Pattern Library)

## When to Use
- After every bug fix (mandatory — not optional)
- After `/fix-single-bug` and `/test-and-verify` complete
- User says "update brain for {BUG_ID}"

## Required Input
| Field | Source |
|---|---|
| `{BUG_ID}` | From fix workflow |
| `{MODULE_NAME}` | From fix workflow |
| Brain path | `knowledge/{MODULE_NAME}/MODULE_BRAIN.md` |

## Steps

### 1. Read Current Bug Fix Context

// turbo
Read the fix details:
- Bug report entry from `bug_report_AI/{module}/CONSOLIDATED_BUG_REPORT.md`
- The walkthrough generated by `/fix-single-bug`
- The current Module Brain: `knowledge/{MODULE_NAME}/MODULE_BRAIN.md`

### 2. Update Brain §10 — Bug Root Cause Register

Add a new entry:

```markdown
### {BUG_ID}: {Bug Title} ✅ FIXED v{VERSION}

**Symptom**: {What the user/tester reported}

**Root Cause**: {What was actually wrong in the code}

**Fix Location**: {file}:{line range}

**Fix Applied**: {What was changed — one line summary}

**Anti-Pattern**: {The wrong pattern that caused the bug}
- ❌ BEFORE: `{exact wrong code}`
- ✅ AFTER: `{exact correct code}`

**Prevention**: {What coding practice would have prevented this?}

**Test Case**: {TC-MODULE-NNN} — {input → expected output}
```

### 3. Update Brain §11 — Code Anti-Patterns Map (if applicable)

If the bug was caused by a coding anti-pattern (wrong selector, wrong variable source, copy-paste error):

```markdown
### AP-{NNN}: {Function Name} — {Anti-Pattern Description} ✅ FIXED v{VERSION}

**File**: {file}:{line}

**What was wrong**:
\`\`\`javascript
// ❌ BEFORE:
{exact wrong code with explanation comment}
\`\`\`

**What is correct now**:
\`\`\`javascript
// ✅ AFTER:
{exact correct code with explanation comment}
\`\`\`

**Verify fix**: Check {file}:{line} — should {describe correct state}.
```

### 4. Update Brain §13 — Field-Level Trace (if data flow changed)

If the fix changed how data flows (different source element, different variable name, different DB column):
- Update the relevant field trace in §13
- Mark the old break point as "✅ FIXED in v{VERSION}"
- Document the new correct flow

### 5. Update Brain §15 — Unit Test Derivation Map

Add new test cases derived from this bug:

```markdown
| TC-{MODULE}-{NNN} | {BUG_ID} | {Scenario} | {Input} | {Expected Output} |
```

### 6. Update Brain §21 — Gaps, Risks & Technical Debt

- If the bug was caused by technical debt → mark the debt item as FIXED
- If the fix revealed NEW technical debt → add a new entry
- If a missing validation was added → remove from "Missing Validations" list

### 7. Update Brain §12 — Function-Level Code Map (if function behavior changed)

If the fix changed what a function reads/writes:
- Update the Reads/Writes/Known Gaps columns for that function

### 8. Update Common Bug Patterns Library

// turbo
Read `bug_report_AI/COMMON_BUG_PATTERNS.md` (if exists).

**If this bug matches an existing pattern:**
- Add `{MODULE_NAME}` to the pattern's "Modules Found In" list

**If this is a genuinely new pattern:**
Add a new entry:

```markdown
### Pattern: {PATTERN_NAME}

**Type**: System / Architecture / Business
**Category**: {Security / Transaction / Logic / ...}
**Detection Rule**: Search for `{grep pattern}` in {file type}

**What It Looks Like**:
\`\`\`
{example of the wrong code pattern}
\`\`\`

**Why It's Wrong**: {explanation}

**Fix Template**:
\`\`\`
{example of the correct code pattern}
\`\`\`

**Modules Found In**: {MODULE_NAME}
**First Found**: {date}
```

### 9. Update Bug Report Status

In `bug_report_AI/{module}/CONSOLIDATED_BUG_REPORT.md`:
- Change bug status: `New` / `In Progress` → `Fixed`
- Add fix date, fix version, and applied-by

### 10. Report to User

Tell the user:
- Brain sections updated: §{list sections updated}
- Pattern library: new pattern added / existing pattern updated / no change
- Bug {BUG_ID} fully closed
- Recommend next action: `/fix-single-bug {NEXT_BUG_ID}` for next Sprint 1 bug
