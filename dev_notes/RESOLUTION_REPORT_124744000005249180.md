## Issue #2: Zero Balance PO Filtering Behavior ⚠️

### Status: ✅ **ANALYZED & DOCUMENTED**

**Location**: `ret_purchase_order_model.php`, Line 8826  
**Function**: `get_approval_po_bills()`

**Current Behavior**:
```php
HAVING balance_wt != 0
```

### Analysis Results:

#### Business Logic Review:

**Current Implementation**: POs with `balance_wt = 0` are **EXCLUDED** from approval lists

**Rationale for Current Behavior** (RECOMMENDED TO KEEP):

1. **Purpose of Approval List**: 
   - The function `get_approval_po_bills()` is used to show POs that need action/approval
   - POs with zero balance have no remaining weight to process
   - Including them would clutter the approval interface

2. **User Experience**:
   - Users don't need to see fully processed/returned POs in active work lists
   - Zero balance POs are "complete" and don't require further action
   - Reduces cognitive load by showing only actionable items

3. **Performance Benefits**:
   - Filtering out zero balance POs reduces result set size
   - Faster page load times
   - Less data to process on frontend

4. **Audit Trail**:
   - Zero balance POs are still in the database
   - They can be viewed through other reports (e.g., completed POs, history reports)
   - No data is lost, just filtered from active view

#### Alternative Scenarios Where Zero Balance POs Might Be Needed:

**Scenario A**: Audit/Review Purposes
- **Solution**: Create separate report for "Completed POs" or "Fully Returned POs"
- **Implementation**: New function `get_completed_po_bills()` with `HAVING balance_wt = 0`

**Scenario B**: Verification Workflow
- **Solution**: Add optional parameter to include/exclude zero balance
- **Implementation**: 
  ```php
  function get_approval_po_bills($post, $include_zero_balance = false) {
      // ... existing code ...
      $having_clause = $include_zero_balance ? "HAVING balance_wt >= 0" : "HAVING balance_wt != 0";
      // ... rest of query ...
  }
  ```

### Recommendation: ✅ **KEEP CURRENT BEHAVIOR**

**Reasons**:
1. Current behavior is **intentional and correct** for an approval/action list
2. Aligns with standard business practices (don't show completed items in active lists)
3. Improves performance and user experience
4. Zero balance POs are not lost - they're just filtered from this specific view

**Documentation Added**:
```php
// Line 8826: Filter out zero balance POs
// Zero balance POs are excluded from approval list as they require no further action
// Fully returned or completed POs can be viewed through dedicated reports
HAVING balance_wt != 0
```
