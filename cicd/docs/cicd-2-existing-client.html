🔧 Existing Client Setup

Add CI/CD to an existing client repo that's already deployed

0 Prerequisites

  • Client repo exists in LOGIMAX-CLIENTS organization
  • Server already has code deployed (cPanel or AWS)
  • SSH access to client server
  • GitHub admin access to client repo

1 Copy Scripts to Server

SSH to the client server and copy the deployment scripts:

Option A: cPanel Server

# Connect to server ssh username@client-domain.com # Create webhooks directory mkdir -p ~/public_html/webhooks # Copy files (run from your local machine) scp scripts/unified-deploy.sh user@server:~/public_html/deploy.sh scp scripts/webhook-handler.php user@server:~/public_html/webhooks/deploy.php scp scripts/rollback.sh user@server:~/public_html/rollback.sh scp maintenance.html user@server:~/public_html/maintenance.html # Make scripts executable chmod +x ~/public_html/deploy.sh ~/public_html/rollback.sh

Option B: AWS Server

# Connect to server ssh -i key.pem ubuntu@ec2-xxx.amazonaws.com # Create directories sudo mkdir -p /var/www/html/webhooks sudo mkdir -p /var/www/releases /var/www/shared # Copy files scp scripts/unified-deploy.sh user@server:/var/www/html/deploy.sh scp scripts/webhook-handler.php user@server:/var/www/html/webhooks/deploy.php # Set permissions sudo chown -R www-data:www-data /var/www

2 Configure Environment

Generate Webhook Secret

# Generate a random secret openssl rand -hex 32 # Output: a1b2c3d4e5f6... (save this!)

cPanel: Add to .htaccess

# Create ~/public_html/webhooks/.htaccess SetEnv WEBHOOK_SECRET "your-secret-here" SetEnv REPO_PATH "/home/username/public_html" SetEnv DEPLOY_SCRIPT "/home/username/public_html/deploy.sh" SetEnv LOG_FILE "/home/username/deploy.log"

AWS: Create Environment File

# Create /var/www/.deploy-env export WEBHOOK_SECRET="your-secret-here" export REPO_PATH="/var/www/html" export DEPLOY_SCRIPT="/var/www/html/deploy.sh" export RELEASES_DIR="/var/www/releases" export SHARED_DIR="/var/www/shared"

3 Add GitHub Secrets

Go to client repo → Settings → Secrets → Actions:

Secret NameValue
STAGING_WEBHOOK_URL https://client-domain.com/webhooks/deploy.php
STAGING_WEBHOOK_SECRET (the secret you generated)
PRODUCTION_WEBHOOK_URL https://client-domain.com/webhooks/deploy.php
PRODUCTION_WEBHOOK_SECRET (the secret you generated)

4 Add Workflow to Client Repo

Create .github/workflows/deploy.yml in the client repo:

# Copy from: templates/client/deploy.yml # Or create manually: name: 🚀 Deploy on: push: branches: [staging, production] jobs: deploy-staging: if: github.ref == 'refs/heads/staging' uses: Logimax-Technologies/retail_v5/.github/workflows/deploy-reusable.yml@main with: environment: staging deploy_mode: simple maintenance_mode: false client_name: ${{ github.event.repository.name }} secrets: WEBHOOK_URL: ${{ secrets.STAGING_WEBHOOK_URL }} WEBHOOK_SECRET: ${{ secrets.STAGING_WEBHOOK_SECRET }} deploy-production: if: github.ref == 'refs/heads/production' uses: Logimax-Technologies/retail_v5/.github/workflows/deploy-reusable.yml@main with: environment: production deploy_mode: symlink maintenance_mode: true client_name: ${{ github.event.repository.name }} secrets: WEBHOOK_URL: ${{ secrets.PRODUCTION_WEBHOOK_URL }} WEBHOOK_SECRET: ${{ secrets.PRODUCTION_WEBHOOK_SECRET }}

5 Add Maintenance Check

Add this to the top of index.php:

<?php // Maintenance mode check if (file_exists('.maintenance')) { header('HTTP/1.1 503 Service Unavailable'); include 'maintenance.html'; exit; }

6 Test Deployment

# Test staging (auto-deploy) git checkout staging git commit --allow-empty -m "Test CI/CD" git push # Check GitHub Actions tab for workflow status
💡 Tip: Check the deploy.log on the server if something fails.
