Mono-Repo Architecture
& Git Feature Branch Workflow

Internal Release — Logimax Technologies

📅 March 10, 2026 📋 Version 1.0 🏢 Logimax Technologies

📋 Executive Summary

We have successfully implemented and deployed a Mono-Repo Architecture with a Three-Layer Override System that allows us to serve multiple clients from a single codebase while preserving client-specific customizations. This replaces our previous approach of maintaining separate Git repositories per client.

First client deployed: Ashoka Jewellers — running on production as of March 7, 2026.

A Git Feature Branch Workflow with standardized naming conventions has been established to ensure clean collaboration, traceable changes, and safe deployments.

🗓️ Meeting Summary — March 9, 2026

Presentation Outcome

The presentation covering Mono-Repo Architecture, Three-Layer Override System, Git Feature Branch Workflow, CI/CD Pipeline, and Server Architecture was delivered to the team. The session completed smoothly.

✅ Architecture

  • Three-Layer Override System (Core → Feature Pack → Client)
  • Dynamic view/model/helper resolution via MY_Loader.php
  • Client config via JSON files (config/clients/*.json)
  • Zero-change client onboarding (folder + JSON = new client)
  • Cookie-based CLIENT_ID persistence for local development

✅ CI/CD Pipeline

  • GitHub Actions workflow (deploy-mono-client.yml)
  • Auto-discovery of clients from config/clients/*.json
  • Webhook-triggered deployment per client per environment
  • Maintenance mode auto-enabled/disabled during deploy
  • Release-based production with symlink swap
  • 5 release history for instant rollback

✅ Server Architecture

  • Staging: direct git pull (fast iteration)
  • Production: clone-based releases with 21 symlinks
  • Shared data directories (uploads, config, logs)
  • Atomic symlink swap (zero-downtime deploy)
  • One-command server provisioning script

✅ Git Workflow

  • Feature branch workflow with PR-based merge
  • Standardized branch naming convention (7 types)
  • Zoho task ID traceability in branch names
  • Protected Production + support branches
  • Squash & merge with code review requirement

🔀 Branch Naming Convention — Quick Reference

Format: <type>/<task-id>-<short-description> — lowercase, hyphens only, 5-7 words

Type Use Case Example
feature/ New functionality feature/5628318-add-hallmark-field
fix/ Small fixes (typo, minor UI) fix/5698123-correct-gst-label
bugfix/ Confirmed tracked bugs bugfix/5698456-login-crash
hotfix/ Urgent production fix hotfix/5712789-payment-failure
chore/ Maintenance / housekeeping chore/5734567-update-dependencies
refactor/ Restructure without behavior change refactor/5745678-modularize-billing
docs/ Documentation only docs/5756789-update-api-docs
