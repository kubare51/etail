⚖️ Staging vs Production

Feature 🟢 Staging 🔴 Production

🟢 Staging Deployment

📥 Fetch All

git fetch --all

📍 Checkout Branch

git checkout staging

💾 Stash Changes

git stash --include-untracked (if local changes exist)

🔄 Reset & Pull

git reset --hard origin/staging && git pull --no-rebase

🔙 Restore Stash

git stash pop (if stashed)

🧹 Clear Cache

Optional: Remove cache directories

🔴 Production Deployment (Symlink)

✅ Approval

GitHub Environment protection requires reviewer approval

🔧 Maintenance ON

touch .maintenance (users see downtime page)

📁 Create Release

/releases/20260108_192500/

📥 Clone Fresh

git clone --depth 1 --single-branch

🔗 Link Shared

Symlink uploads, logs, config files

⚡ Atomic Swap

ln -sfn release new && mv -Tf new current

🔧 Maintenance OFF

rm .maintenance

📧 Send Report

Jenkins-style HTML email to team

📁 Production Directory Structure

/var/www/ (or /home/user/)
├── current → releases/20260108_192500/  # Symlink (web root)
│
├── releases/
│   ├── 20260108_180000/  # Previous (for rollback)
│   ├── 20260108_190000/  # Previous
│   └── 20260108_192500/  # Current ← active
│
├── shared/
│   ├── logs/            # Persistent logs
│   ├── uploads/         # User uploads
│   ├── img/             # Product images
│   ├── database.php     # DB config (copied)
│   └── global_configs.php
│
└── .last_release        # For rollback tracking

🔄 Instant Rollback

⚡ Rollback in under 1 second!

Just swap the symlink - no file copying needed.

# List available releases
./rollback.sh list
# Rollback to previous release
./rollback.sh previous
# Rollback to specific release
./rollback.sh 20260108_180000
